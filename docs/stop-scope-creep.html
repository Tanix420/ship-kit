How to stop AI agent scope creep (the PLAN.md pattern)

The classic vibe-coding disaster: you ask for a dark-mode toggle. Twenty minutes later the agent has renamed half your files, "improved" three unrelated modules, and the original button is a checkbox in a settings page you never asked for. Nothing is broken, exactly. Nothing is finished, either.

The cause is not stupidity — it's that "fix what you see" is a reasonable default for a helpful assistant and a terrible default for a contributor. Agents don't have a concept of authorized work. So give them one: a file that defines what is allowed to exist.

The pattern: PLAN.md, scope of record

# PLAN.md — scope of record

**Rule for agents:** if it is not in this table, do not build it.
Propose by adding a row under "Proposed" and asking the owner.

| # | Feature                          | Status   | Notes |
|---|----------------------------------|----------|-------|
| 1 | Static page served from public/  | shipped  |       |
| 2 | GET /api/health JSON endpoint    | shipped  |       |
| 3 | Dark-mode toggle                 | proposed | waiting approval |

## Definition of shipped
verify.sh green + a test covering the feature + this table updated.

Three rules do all the work:

  1. Not in the table = doesn't exist. The agent may not implement ideas, only rows.
  2. Ideas go to "Proposed", never to code. The agent's good ideas are welcome — as a proposal you approve.
  3. One row per task. Drive-by refactors are out of scope by definition.

The prompt that enforces it

Before you write any code: list the exact feature(s) from PLAN.md you
are about to implement. If your planned work includes anything not in
PLAN.md, add it to "Proposed" and ask me first. Do not refactor files
unrelated to this task.

Why it works: it forces a plan before generation, when it's cheap to correct, instead of a diff after, when you're negotiating with your own codebase. Pair it with the read-order rule in AGENTS.md (PLAN.md is file #2 the agent reads) so the agent can't claim it never saw it.
