AGENTS.md template for AI coding agents (with a verify loop)

AGENTS.md is a plain markdown file at your repo root that tells any AI coding agent how to behave in this project: what stack it is, what the rules are, what "done" means, and what it may never touch. Think of it as a README written for a very fast, very literal new hire who has never met you.

The template below is the actual contract that ships in Ship Kit lite — free, MIT, working, and tested. Copy it, or clone the repo and get it plus a demo app that already passes its own gate.

The template

# AGENTS.md — project contract

This file is the single source of truth for any AI agent working here.
If any other file conflicts with this one, this file wins.

## 0. Read order
1. AGENTS.md (this file)
2. PLAN.md (current scope — what is allowed to exist)
3. README.md (how to run things)

## 1. The verification loop (most important rule)
You are NOT done when the code looks right. You are done when:

    ./verify.sh

exits 0 and prints ALL CHECKS PASSED.
- Run it after every change, before you report anything.
- If it fails: fix the code and re-run. If it fails twice for the same
  reason, STOP and report the exact error. Do not keep guessing.
- Never edit a test just to make it pass. If a test looks wrong, say so
  in one sentence and ask the owner.

## 2. Scope guard
- Implement only features listed in PLAN.md.
- A feature not in PLAN.md does not exist. Propose it under "Proposed"
  and ask the owner. Do not implement it "while you're in there".
- One feature per task. No drive-by refactors.

## 3. Conventions
- Stack: [YOUR STACK HERE]. Dependencies: [none by default].
- Tests live in [test/] using [YOUR RUNNER]. Run: [COMMAND].
- Build outputs to [dist/] (never commit it).
- File names: kebab-case. Functions: small, named, boring on purpose.
- Comments explain WHY, not WHAT.
- No new dependencies without a PLAN.md decision by the owner.

## 4. Never touch without owner approval
- Dependency manifests (package.json / requirements.txt / go.mod)
- CI configs (.github/), LICENSE, this file's rules

## 5. Commit discipline
- Conventional commits: feat:, fix:, docs:, chore:, test:.
- One logical change per commit. verify.sh green before every commit.

## 6. Definition of Done
- [ ] ./verify.sh exits 0
- [ ] New behavior has a test
- [ ] PLAN.md status updated
- [ ] No TODO/FIXME left in the diff
- [ ] Honest summary: what you did, what you didn't, what's untested

Why the verify loop is the part people skip

Most AGENTS.md files you'll find online are style guides: naming, tone, folder layout. Fine — but they don't change the failure that costs you days: the agent believing it is done. The fix is to make "done" external and observable. A script that runs syntax checks, tests, and a build, exits non-zero on any failure, and whose full output the agent must paste back to you, converts "trust me, it works" into evidence you can read in ten seconds.

Which tools read it?

OpenAI Codex reads AGENTS.md as a standard. Other tools use their own entry files (Claude Code reads CLAUDE.md; Cursor has its own rules files). The pattern that works everywhere: keep one AGENTS.md as the source of truth, and make the tool-specific files thin pointers to it — one line, "read AGENTS.md, it wins on conflict". Ship Kit ships that pointer file too, so you never maintain two rulebooks.
